## 비교 방법

- 저장소의 알려진 `examples/hello.c`를 Linux 임시 폴더에서 `gcc -g -O0`로 컴파일했습니다. 직접 실행해 `Hello from lhlinux` 한 줄을 출력하고 0으로 종료함을 확인했습니다. 사용자 입력을 읽는 코드는 없습니다.
- 설치된 로컬 `qwen2.5-coder:0.5b`를 사용했습니다. 외부 유료 AI 요청이나 모델 다운로드는 하지 않았습니다.
- 동일한 바이너리와 동일한 영문 한 문장 요약 질문을 사용했습니다. 먼저 READY 요청으로 모델을 준비했고, 준비 요청은 7.639초에 완료됐습니다.
- 다른 테스트가 끝난 뒤 compact → standard → standard → compact 순서로 각 2회 요청했습니다. provider 제한은 요청당 90초였습니다.
- 아래 요청 시간은 Linux 내부에서 컨텍스트 준비·CLI 점검·모델 응답을 합쳐 측정한 값입니다. PowerShell/WSL 진입 시간은 제외했습니다. 순수 추론 시간이나 생성 토큰 수를 따로 측정하지 않았습니다.

| 설정 | 입력 크기 | 요청 1 | 요청 2 | 시간 중앙값 | 정상 종료 | 설명 정확도 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| compact | 4096바이트 | 12.233초 | 2.171초 | 7.202초 | 2/2 | 0/2 |
| standard | 11858바이트 | 13.907초 | 4.558초 | 9.232초 | 2/2 | 0/2 |

정확도는 실제 출력 문자열과 핵심 동작을 설명하면서 소스에 없는 동작을 주장하지 않는지를 수동 판정한 결과입니다. JSON의 `mentions_exact_greeting`은 문자열 일치만 검사하는 보조 지표이며 정확도 점수가 아닙니다.

| 실행 순서 | 관찰된 응답 | 수동 판정 |
| --- | --- | --- |
| 1 / compact | 출력 문자열은 맞지만 표준 입력을 읽는다고 주장 | 잘못된 동작 추가 |
| 2 / standard | `puts`가 `hello`를 출력한다고 설명 | 실제 출력 문자열과 불일치 |
| 3 / standard | `puts`를 반복 호출한다고 설명 | 실제 호출 횟수와 불일치, 출력 설명 누락 |
| 4 / compact | 시작·정리 함수 호출 관계만 설명 | 핵심 출력 동작 누락, 부정확한 호출 관계 |

입력량은 약 65.5% 줄었습니다. 하지만 각 2회뿐이고 응답 길이·서버 캐시·생성 난수 등을 통제하지 않았으므로 시간 차이를 일반적인 속도 향상으로 해석할 수 없습니다. 특히 더 짧은 오답을 빠르게 생성한 것을 성공으로 세지 않았습니다.

## 발견 사항과 대조 시험

compact 프롬프트를 직접 확인하니 `main` 역어셈블리가 인자 준비 도중 잘려, 실제 `puts` 호출이 포함되지 않았습니다. 제한된 역어셈블리 공간 일부를 도구 출력 헤더와 `_start`가 차지하고 있었습니다. 문자열 목록에는 정확한 인사말이 있었지만 함수 동작을 확인할 근거가 불완전했습니다.

별도의 대조 시험에서는 C 소스를 포함한 172바이트 입력을 직접 로컬 모델에 전달했습니다. 1.461초에 “The program outputs "Hello from lhlinux" when run.”이라고 정확히 응답했습니다. 이 1회 결과는 짧고 직접적인 입력이 유리할 가능성을 보여주지만, 바이너리 분석과 조건이 달라 어느 설정이 오답의 유일한 원인인지 증명하지는 않습니다.

다음 수정에서는 단순 바이트 절단으로 중요한 동작이 사라지지 않도록 입력 구성을 보완하고, 결과 정확도를 별도 회귀 기준으로 검증해야 합니다. 현재 테스트 모드 표시는 유지합니다. 이번 시험에서는 제품 코드를 수정하지 않았습니다.
